# 视频音频死按钮 — 根因定案与修复验收(0.5.27,2026-09-04)

## 根因链(三角闭合,全部 L3 落盘)

1. **VSCode 出厂 libffmpeg 无 AAC 解码器**(本机二进制验证):
   `nm -gU ".../Electron Framework.framework/Versions/A/Libraries/libffmpeg.dylib"` 导出解码器全集 =
   `ff_h264 / ff_flac / ff_mp3 / ff_pcm_* / ff_vorbis / ff_vp8` — **无 ff_aac_decoder**(仅 `ff_aac_profiles` 字符串表)。
   上游同证:microsoft/vscode#329811(Linux 实测 libffmpeg 无 aac_decoder,换原版库恢复)、#310736(macOS MP4+AAC 内建播放器无声)。
2. → mp4(H.264+AAC)在 workbench 里 **H.264 可解(有画面)、AAC 不可解**。
3. → Chromium Modern Media Controls 源码:`media_controls_impl.cc OnVolumeChange()` 给 mute 按钮挂
   `disabled = !MediaElement().HasAudio()`;`media_control_mute_button_element.cc DefaultEventHandler` 以 `!IsDisabled()` 门控
   → **mute 按钮点击零执行、图标冻结**(play/seek 正常)——与用户实测"死按钮"签名一一对应。
4. 历史一致性:mp3/wav(自由编解码,VSCode 可解)曾正常出声;六轮视频声音修复对 AAC 全部无效。

## 方法学定案(本 Session 探针)

- CDP 合成鼠标输入**无法驱动 UA shadow 控件**(rig c1 裸 `<video controls>` 对照:点击全死)——自动化不可测是原生控件的结构性缺陷。
- rig(headless+windowed Chrome=有 AAC)无法复现用户症状——进一步反证环境级(VSCode 缺解码器)而非 DOM 级。
- `elementFromPoint` 扫控件条:除 14px 四角把手外无任何拦截层;`muted` 属性读写正常;音轨解码正常(有 AAC 的 Chrome)。

## 修复架构(双刀)

1. **mp-mb 自研控件条**(弃 `controls`):play/pause + time + seek + mute + volume,内缩悬浮胶囊(避让四角把手);
   video/audio 共用 `buildMediaBar`;unmute 只在按钮/滑条手势内(autoplay 政策安全)。S4 ▶fallback 删除(被子集覆盖)。
2. **AAC 编解码自由路由**:`navigator.mediaCapabilities.decodingInfo` 探测 AAC(fail-open)→ AAC 家族(mp4/mov/m4v/m4a/aac)
   改走 `/transcode`;server 双路:**h264 源 → `-c:v copy + libmp3lame` remux fMP4(实测 39s 片 0.46s = 85× 实时)**,
   非 h264(avi-mpeg4/prores/hevc)→ webm/VP8/Opus(scale=640)。全部落在 VSCode 实持解码器集合(h264/mp3/pcm/vorbis/vp8 + Chromium 内建 libopus)。
3. **🔴-1 回退**:转码路死(无 ffmpeg 404)且原生可播 → 回退 `previewUrl` 一次(画面保住;声音在无 AAC+无 ffmpeg 宿主本就无解)。
