# 09 — 竞品与差异化矩阵

> 调研穷尽 VSCode 媒体预览生态（confidence=high，WebSearch + marketplace + 源码）。结论先行：**没有任何扩展做到"原生 Explorer 悬停→浮动窗口"**，微软自己也只能 patch core（issue #270270 / PR #279743 改 explorerViewer.ts）。本项目空间是真实真空，非重复造轮子。

## 一、竞品架构对比

| 扩展 | 安装量 | 触发 | 位置 | 架构 | 格式 | 维护 |
|---|---|---|---|---|---|---|
| **Image Preview**(kisstkondoros.vscode-gutter-preview) | 4.19M | editor 内悬停代码里的图片路径/URL/import | editor gutter + hover | Decoration API + HoverProvider + Language Server | 图片 | 2024-12 更新 |
| **vscode.media-preview**(Microsoft，内置) | 内置 | 单击文件 → 打开为 editor tab | docked editor tab（可 split/drag 到任意 editor group） | Custom Editor API + Webview | 图片/视频/音频 | 随 VSCode 更新 |
| **Image Preview On Hover**(GarvitChainani) | 待核实 | editor hover | editor | HoverProvider | 图片 | 待核实 |
| **glINT / SVG Preview / PDF Preview / 字体预览类** | 各自小众 | 打开为 tab / 命令 | docked | Custom Editor / Webview | 单格式 | 各异 |
| **filesize-hover-explorer** | 小众 | Explorer 悬停 | tooltip | FileDecorationProvider tooltip | 仅文本（文件大小） | — |
| **本项目**(TIER1) | — | **原生 Explorer 悬停** | **浮动 popup（四角缩放+四象限定位）** | **workbench DOM patch overlay** | **图片/视频/音频/字体/PDF/3D** | — |

## 二、关键发现

1. **最大竞品不碰 Explorer 树**：Image Preview(4.19M) 只在 editor 内代码路径上预览（gutter+hover），印证"Explorer 树 hover"是未被占领的空白。
2. **内置方案固化 docked 范式**：`vscode.media-preview` 用 Custom Editor + Webview，预览作为 editor tab 打开。用户已习惯"单击→docked tab"。
3. **tooltip 机制在 Explorer 树可用但仅文本**：filesize-hover-explorer 用 FileDecorationProvider tooltip 在 Explorer 显示文件大小（文本），证明 tooltip 通道在，但 [11 R1](11_rejected-by-design清单.md) 已证 `MarkdownString` tooltip 无法注入内置 Explorer 的 tree item。
4. **微软自己也 patch core**：issue #270270（2025-10 open，Backlog）对应 PR #279743 直接改 VSCode core（explorerViewer.ts）非扩展 API，至今未 merge → 反证 public API 不足以做 Explorer hover preview。本项目 patch workbench.html 是**对称合理选择**。
   - ⚠️ 待核实：critic 警告"PR #279743 查不到公开信息可能幻觉"。issue #270270 真实存在且未解决，主结论不依赖该 PR；但发布前应核实，避免文档引用幻觉（[10 RK11](10_风险登记册与spike验证.md)）。

## 三、本项目的差异化（凭什么不被替代）

| 维度 | 本项目 | 内置 media-preview / 竞品 |
|---|---|---|
| **触发** | 悬停即看（不打开文件、不切 tab） | 单击打开 / editor 内路径悬停 |
| **位置** | 浮动 overlay，不抢占 editor 区 | docked tab 占 editor 区 |
| **格式** | 6 类统一入口 | 内置=图片/视频/音频；专用扩展各管一种 |
| **交互** | 四角缩放 + 四象限智能定位 | dock 分隔条 / 无 |

**核心差异化 = "悬停原生 Explorer + 浮动 + 多格式统一入口"**，这是竞品真空的根因（public API 做不到，见 [00](00_总览与架构决策.md) TIER3 论证）。

## 四、风险：被官方替代的窗口

- **图片子场景**：若 VSCode 合入 PR #279743（原生 Explorer 图片 hover），图片这块最大市场会被官方吃掉。
- **应对**：本项目持续差异化于**多格式（视频/PDF/字体/3D）+ 浮动可缩放交互**，而非仅图片。监控 PR #279743 状态，若合入则重心转向多格式。

## 五、市场教育成本（诚实声明）

用户已习惯 docked/gutter 范式（4.19M 装 gutter-preview + 内置 media-preview），"Explorer 悬停浮动预览"是新交互。项目需承担一定的市场教育成本——这反映在 README/demo 必须把"为什么这个交互比 docked 好"讲清楚。
