# 起播首帧闪白 — 根因与修复（0.5.38，2026-09-23）

> 📕 起源:用户报 MP4 悬停起播"开始的几帧连续闪白几下"。原文件 luceo_web `fd2b-64-stab.mp4` 已丢失(全盘+git 历史无),以暗色生成视频+真实 animatic 替身复刻研究。

## 判定(诚实两通路)

**通路一(已修):无帧透明窗。** `renderVideo` settle 在 `loadedmetadata`(readyState=1,**零解码帧**)即 `replaceChildren` 插入 video 并 `play()`;首帧提交合成器前,video 元素按规范**完全透明**(Chromium UA 样式表 [html.css](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/third_party/blink/renderer/core/html/resources/html.css) 无 background;[WHATWG rendering](https://html.spec.whatwg.org/multipage/rendering.html#video)"represents nothing")→ 透出 #mp-popup 底=color-mix(editorWidget-background 72%,transparent)+backdrop-filter。Playwright 复刻(真 overlay CSS+Range 服务):insert 后 rs=1 真实空窗 26-45ms(轻载;真机负载更长),canvas 亮度 0=不可画。

**通路二(未定谳,留用户验证回路):backdrop-filter 图层光栅化。** 否定重查 agent 定罪的关键:用户主题=**One Dark Modern(暗色)**→editorWidget-background≈深灰→通路一透出的是**暗玻璃非白**。"白+连续几下+主题无关"的最强竞争解释=popup/fname/rail/mb 四处 backdrop-filter 的图层(重)光栅化在老 GPU(MBP11,4 Iris Pro 5200/R9 M370X)上的白块伪影([chromium#40735345](https://issues.chromium.org/issues/40735345) 同族;入场动画期多次重光栅化="连续几下")。探针环境(渲染环拥塞 11.6s 输入延迟+窗口遮挡零合成帧)无法本地复现,留用户 Cmd+Q 后目验;若闪白残留→下轮做 backdrop 消融 A/B。

替身内容排除:两替身首 15 帧 YAVG≈45/48(暗)→"文件自身白帧"对替身证伪(原文件系白墙稳定变体,内容白可能性无法排除——机制研究独立于内容)。

## 修复(通路一,业界模式对齐)

调研([qr-scanner](https://github.com/Nimiq/qr-scanner)/[Codrops·Shopify Spring'26](https://tympanus.net/codrops/2026/06/26/engineering-the-web-experience-behind-shopifys-spring-26-edition-everywhere/):**opacity 0→首 rVFC 揭示**是共识;禁 display:none(停解码);rVFC 两坑=离屏不触发([chromium#40239565](https://issues.chromium.org/issues/40239565))+晚注册漏首帧→必须 play 前注册+多信号兜底):

1. **首帧揭示闸**:video 创建即 `opacity:0`;settle 插入后、play 前注册 `requestVideoFrameCallback` 主信号(唯一"帧已提交合成器"级)+ `loadeddata`×双 rAF 次级 + 500ms 兜底;幂等 reveal(epoch+settled 三守卫,迟到 reveal 不触碰已换代元素)。
2. **preload 条件式**:原生直读=auto(预热首帧缩短空窗);转码流(mkv/avi/flv)保持 metadata——auto 会拉动 ffmpeg 前瞻转码白烧 CPU(否定重查 AMEND)。
3. **D1 附修**:600ms 兜底走默认 400×300 时,晚到 metadata 在**揭示前**补正几何(reveal 推迟可见性→不可见期改几何零跳动;原=永久错误几何;修正窗扩至 (600,1100)ms)。
4. **D2 附修**:模块 `activeVideo` 引用,dispose 切断离屏未 settle master video 的 /preview 孤儿拉取(镜像 0.5.32b activeTwin——对抗审发现当年只修了 twin 漏了本体;反复进出悬停曾累积并行拉取拖慢下次起播)。

## 教训回流

1. **透明窗是规范级行为**:任何"元素先可见、内容后到"的 UI 都有此窗——揭示闸(opacity 0→首帧信号)应成为此类渲染器的标配;首帧信号只有 rVFC 是"已上屏"级,loadeddata/canplay 是解码侧。
2. **子串锚可被注释包裹绕过**:行锚(`^`+m)或行为锚才是防突变;本项目两轮实证(M9/M11)。
3. **探针环境的三重伪影**(拥塞输入延迟/窗口遮挡零合成帧/screencast 更新驱动)——真机合成器级验证在此机器上不可靠,用户目验是最终真值;链路插桩([MPDBG])可分离"代码死"与"环境慢"。
4. **原文件丢失也要继续**:替身+机制复刻可研究内容无关的机制;但"用户症状=该机制"的归因必须诚实标注(两通路)。
