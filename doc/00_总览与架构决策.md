# VSCode 资源预览插件 — 总览与架构决策

## 项目定位

一个 VSCode 扩展(+ workbench patcher),在**原生资源管理器**(Explorer 文件树)中,**鼠标悬停**到图片/视频/PDF/字体/音频/3D 资源时,弹出**浮动预览窗口**(四角可缩放 + 智能四象限定位 + 尺寸记忆)。

> **v0.1 交互定调**（用户决策 2026-08-08）：浮动弹窗 + **四角缩放** + **智能四象限定位**（按文件项在视口位置自动选左上/左下/右上/右下展开，避开文件项与屏幕边缘）+ 尺寸记忆。**不做自由位置拖拽**（理由见 [11 F1](11_rejected-by-design清单.md)）。

## 架构决策：TIER 1 — DOM Patch Overlay

### 为什么选 TIER 1

经 5 维深度调研（8-agent 工作流，读 microsoft/vscode 源码 + 竞品 + CSP + checksum + 纯 API 穷尽验证），结论：

| 需求 | TIER 1（DOM patch） | TIER 3（公开 API） |
|------|-------------------|-------------------|
| 悬停**原生**资源管理器触发 | ✅ mouseenter on Explorer item | ❌ 无法注入内置 File Explorer（[09](09_竞品与差异化矩阵.md)、[11 R1](11_rejected-by-design清单.md)） |
| 浮动窗口（非 docked） | ✅ 注入 `<div>` position:fixed | ❌ WebviewPanel 永远 docked；无浮动 overlay API |
| 四角缩放 + 四象限定位 | ✅ JS 四角 resize handle + 定位算法 | ⚠️ dock 面板拖分隔条（非浮动） |
| 多类型真实预览 | ✅ Chromium 渲染(img/video/pdf.js/three.js) | ⚠️ tooltip 仅静态图片（[11 R2](11_rejected-by-design清单.md)） |

TIER 1 是**唯一同时满足全部需求**的路径。**关键佐证**：连微软自己的 issue #270270（"Explorer 悬停图片预览"）对应方案都是改 VSCode core（explorerViewer.ts）非扩展 API——public API 做不到，本项目 patch workbench.html 是对称合理选择（[09](09_竞品与差异化矩阵.md)）。

### 核心妥协（已知 + 已评估）

1. **VSCode 更新必断** — workbench 文件被覆盖 → 自愈 patcher 自动 re-patch（同 cc-status-dot 模式）。**但见"失败域边界"**：自愈只覆盖"文件被覆盖"，不覆盖 sudo 权限/代码签名失效/checksum 抑制失败三类新失败。
2. **Marketplace 不可发布** — patch 内部文件违政策。通过 GitHub + `npx` 分发（[11 R4](11_rejected-by-design清单.md)）。
3. **"安装损坏"警告** — patch `product.json` checksum 抑制（**重算 SHA256 填回**为主；删 key Spike 4 实测在 reload 场景仍弹损坏已弃用，[01](01_自愈patch机制设计.md#checksum-抑制productjson-patch)）。校验失败仅警告通知+[Unsupported]标记，**不禁用不阻止启动**（调研读 integrityService.ts 源码确证）。
4. **macOS 可能需 codesign 重签** — 改 `.app` 内文件 invalidate Apple 代码签名，可能需 `codesign --remove-signature`（[10 Spike 5](10_风险登记册与spike验证.md)，待验证）。
5. **永久维护税** — VSCode 月更可能打断 patch/选择器/CSP。这是 TIER1 的固有成本（[10 RK8](10_风险登记册与spike验证.md)），单人维护需正视。

### 不选其他路径（详见 [11 rejected-by-design](11_rejected-by-design清单.md)）

- **TIER 3 纯 API**：无法注入内置 Explorer tooltip，无浮动 API（[11 R1](11_rejected-by-design清单.md)）。
- **TIER 3 降级（自建树+tooltip 静态图）**：放弃原生 Explorer + 仅图片，是另一个产品形态（[11 R2](11_rejected-by-design清单.md)，保留为降级预案）。
- **TIER 2 Electron sidecar**：150MB/独立 OS 窗口/无法定位鼠标，被 TIER1 dominate（[11 R3](11_rejected-by-design清单.md)）。

## ⚠️ 与 cc-status-dot 的关键差异（失败域不同级别）

> 工作流 critic 重点纠偏：原 00/01 "直接复用 cc-status-dot 架构" 的措辞**低估了失败域差异**。两者 patch 机制相似，但**patch 目标的性质根本不同**：

| 维度 | cc-status-dot | 本项目 |
|------|--------------|--------|
| **patch 目标** | `~/.vscode/extensions/anthropic.claude-code-*/extension.js` | VSCode app 目录的 `workbench.html` + `product.json` |
| **目标性质** | 用户扩展目录里**第三方扩展**的文件 | **IDE 核心二进制** |
| **文件权限** | 用户可写（extensions 目录） | macOS `/Applications/`、Linux `/usr/share/` 可能需 sudo |
| **代码签名** | 扩展文件无签名 | VSCode app 有 Apple 签名 → 改文件 invalidate（[10 Spike 5](10_风险登记册与spike验证.md)） |
| **checksum 校验** | 无 | VSCode IntegrityService 校验 product.json checksums（须抑制，[02](02_workbench注入设计.md)） |
| **失败域** | 仅状态点不显示 | 整个编辑器（"安装损坏"警告、签名失效、启动失败可能） |
| **更新触发** | CC 扩展更新（频率低、用户可控） | VSCode 月更（频繁、自动） |
| **patch 生效方式** | Reload Window 即生效（EH 重载 extension.js） | **必须 Cmd+Q 完全退出重启**——Reload Window 走 Chromium disk cache 不重读 workbench.html → patch 不生效，且旧 workbench 与新 product.json checksum 失配弹"安装损坏"（Spike 实测 2026-08-08，[10 RK13](10_风险登记册与spike验证.md)） |

**结论**：patch 机制（detectAndPatch/自愈/IIFE/`npx` 分发）可复用 cc-status-dot 模式；但**失败域高一个数量级**。自愈 re-patch 只覆盖"文件被覆盖"一种失败，sudo/签名/checksum 三类新失败需独立处理（见 [01 失败域边界](01_自愈patch机制设计.md#失败域与自愈边界)）。

## 整体架构

```
用户安装: npx -y vscode-media-preview@latest
         ↓
    patcher 运行(TIER 1 self-healing)
    ├── 定位 VSCode 安装路径(三平台，多候选路径，[05](05_三平台路径与权限.md))
    ├── patch product.json checksums(重算填回为主，删 key 实测失败已弃用，[01](01_自愈patch机制设计.md#checksum-抑制productjson-patch))
    ├── patch workbench.html:
    │     ├── 删/改 CSP meta(connect-src/img-src/media-src 加 http://127.0.0.1:*，[02](02_workbench注入设计.md))
    │     └── 注入静态 <script src="./mp-overlay.js">(旁路 Trusted Types，[02](02_workbench注入设计.md))
    ├── 复制 overlay.js 到 workbench 目录
    └── 提示用户完全退出重启（Cmd+Q；Reload Window 用缓存不重读 workbench.html，patch 不生效）

    VSCode 启动后:
    ├── Extension Host(EH, Node.js)
    │     └── localhost HTTP server(:17741, 绑 127.0.0.1 + 鉴权，[04](04_EH与Renderer通信协议.md))
    │           ├── /preview?file=X&type=image → JSON {mime,base64}
    │           ├── /preview?file=X&type=video → HTTP range stream (206)
    │           ├── /preview?file=X&type=pdf|3d → binary stream
    │           ├── /config → type→mime 权威映射(单一真相源)
    │           └── /resolve?name=X → {path}(文件索引，[06](06_DOM选择器容错策略.md))
    │
    └── Renderer(Workbench DOM, Chromium)
          └── overlay IIFE(注入的静态脚本)
                ├── 等 Explorer DOM 就绪(MutationObserver，[06](06_DOM选择器容错策略.md))
                ├── mouseover 委托 → 解析文件名 + 扩展名
                ├── 判断是否媒体文件 → 是 → 显示浮动 popup
                ├── fetch localhost:17741 → 获取预览内容
                ├── popup <div>(createElement，遵守 Trusted Types):
                │     ├── position: fixed(四象限智能定位，[03](03_浮动预览弹窗设计.md))
                │     ├── 四角 resize handle(四角缩放)
                │     ├── <img>/<video>/<canvas>(按类型，渲染器矩阵 [08](08_富媒体渲染器矩阵.md))
                │     └── localStorage['mpSize'] = {w,h}(尺寸记忆)
                └── mouseleave → hide popup(延迟 200ms 防抖)
```
