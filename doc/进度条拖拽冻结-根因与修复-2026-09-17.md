# 进度条拖拽冻结 — 根因与修复（0.5.37，2026-09-17）

> 📕 起源:用户实测——悬停 animatic-v9.mp4(h264+aac,twin 双元素)正常播放有声音;**拖进度条到最开头后继续播放,进度条不动了**。

## 根因(Playwright 真机复现定案)

`buildMediaBar` 的 `sync()` 以 **环境焦点推断拖拽中**:

```js
if (document.activeElement !== seek) seek.value = ...  // 0.5.27d 🟡-1"拖动中不被覆写"
```

推演链(真机逐事件实证):

1. pointerdown 落 seek → range 得焦 → `activeElement = seek`
2. 拖动:每 input 写 `media.currentTime`(跳转/拖动都生效)
3. 松手:**Chromium 对 range 松手后从不自动 blur**——焦点恒留
4. 继续播放:timeupdate(~4Hz)→ sync() → 守卫恒 false → `seek.value` 永不更新
5. 点其它可聚焦控件(按钮等)偶发 blur = 偶发"自愈"→ 用户感知"时有时无"

Playwright 最小复现(真实 Chromium):拖后 `activeElement=seek`、模拟媒体时间 14880→15120ms 推进而 seekValue 冻结 0、覆写计数停 363;点击按钮后恢复(383/367)。

**本质**:把"用户正在拖拽"这一**交互状态**推断自**全局环境焦点**——正是 [02_简单架构清单](../../../../架构想法/02_简单架构清单.md) 反对的环境态耦合(状态须显式 owned,勿耦合全局环境)。range 的焦点语义(拖后不释放)与该推断的隐含假设(拖完=失焦)根本不兼容。

## 业界调研(实读三库源码)

| 库 | 拖拽态 | 复位通道 |
|---|---|---|
| video.js | `player.scrubbing(bool)` 显式标志;scrubbing 期换数据源(getCache().currentTime) | document mouseup/touchend,disable()/dispose() 再清 |
| plyr | 借原生 `media.seeking`;input 连续写 currentTime | mousedown/mouseup/keydown/keyup/touchstart/touchend 六事件 |
| media-chrome | `dragging` 反射属性(每帧重算 `buttons===1`) | **window pointerup(once)** + pointerleave;**根本不监听 change** |

关键事实(HTML spec/MDN/chromium-bugs 实证):**change 有"拖回原值不发"的规范级丢失路径**——拖出去又拖回原值松手,input 全程发而 change 不发。业界无一库单点信任 change。

## 修复(显式交互态,四通道复位)

```js
var scrubbing = false, lastSeekTs = 0;   // 闩锁 + 输入时间戳
seek input   → scrubbing = true; lastSeekTs = Date.now(); media.currentTime = ...
var seekEnd  → if (!scrubbing) return; scrubbing = false; sync();
change/blur/pointerup/pointercancel → seekEnd   // 四通道(元素级:原生 range 隐式指针捕获)
sync 守卫    → if (!scrubbing && Date.now() - lastSeekTs > 150) seek.value = ...
```

- **闩锁**:扛"拖中按住静止"(纯时间戳会在 150ms 后误覆写拇指)
- **150ms 去抖**:接棒原焦点守卫兼负的键盘修磨保护(按住方向键 input+change 每键成对连发,时间窗内不覆写)
- **四通道复位**:change 主通道(鼠标松手+键盘每键成对)+ blur(键盘/detach 失焦)+ pointerup(**change 丢失路径兜底**——拖回原值场景)+ pointercancel(系统手势打断)。全元素级(原生 range 隐式指针捕获→窗外释放也达元素),零 document 级监听(无每渲染累积)
- vol 滑条同款(volScrub/lastVolTs/四通道)——mute 按钮改音量后滑条跟随,原焦点推断同族冻结

## 验证链

- **gate8 行为锚 4b/4c**:拖中保护(scrubbing)→ 闩锁独立防线(170ms 过去抖窗后仍不覆写——杀"删 input 置位"突变)→ 冻结回归杀(change+去抖窗外必覆写,注入 activeElement=seek 复现旧失败模式)→ pointerup 兜底(change 丢失路径)。桩补 `activeElement` 可注入(原桩无此属性→旧守卫恒过=空转绿,盲区根因)
- **gate7 六钉**:文件级禁 `document.activeElement` + 闩锁/去抖/四通道/守卫逐字符钉
- **突变矩阵 9/9 全杀**(焦点推断回归/删 change/删 pointerup/去抖 150→0/vol 两族/删 seekEnd resync/删 input 置位)
- **真机 CDP 端到端**(用户原文件 animatic-v9.mp4,独立 17842 探针服务器与主实例 17741 隔离):拖到最开头(t=0.106)→播放→ t 与 seek.value 同步推进(1.0s/25‰ → 2.4s/63‰),twin 音频跟随(2.22s),**焦点遗留在场也不冻结** → RIG37-PASS
- **对抗终审**(fresh agent,创造者不自批):零🔴/1🟡(锚盲区"删 input 置位"同 tick 逃逸——已补 170ms 闩锁锚)/4🔵(两条已修:注释纠偏+陈旧头注释;两条记录:M4 仅数值钉杀=HIDE_DELAY 同惯例、activeElement 文件级禁令或误伤未来 a11y 焦点功能)
- **A/B 对照**:重悬停不自动起播(探针环境,页内 play() 即解)在 0.5.36 同款存在——**预存环境行为,非本次回归**;用户实际悬停起播正常

## 教训回流

1. **交互状态禁从环境推断**(焦点/activeElement/坐标轮询皆是)——须显式 owned 事件状态机,否则环境语义变化(如 range 焦点不释放)即成潜伏 bug(本例自 0.5.27d 潜伏 10 个版本)
2. **桩不表达的环境属性 = 空转绿**:vm 桩无 activeElement → 守卫恒真 → 行为锚永不可能红。补桩属性=让失败模式可表达
3. **CDP 拖拽须带 buttons:1**(mouseMoved 无 buttons=悬停移动,原生滑条不跟手);探针与主实例的**媒体服务器端口/令牌冲突**用独立端口+独立 config 隔离
